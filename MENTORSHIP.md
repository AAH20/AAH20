# Learning, contribution, and mentorship

This guide is a practical route into the public projects. Every repository remains an independent system with its own scope, dependencies, tests, benchmark protocol, and evidence limits.

## Explorer

1. Choose a project from the [profile’s guided routes](README.md#choose-your-path).
2. Read the project README, especially prerequisites, quickstart, tests, and limitations.
3. Run the smallest documented example without changing the environment.
4. Record what the example demonstrates and what it does not demonstrate.

## Builder

1. Select a narrowly scoped issue or improvement in one repository.
2. Reproduce the current behavior before editing.
3. Add or update a test that captures the behavior or failure.
4. Run the project’s documented checks and report the exact commands and results.
5. Open a pull request describing the change, evidence, and remaining limitations.

## Researcher and mentor

1. Choose an evaluation question with a declared workload and baseline.
2. Reproduce the baseline on the documented environment.
3. Record outputs, versions, seeds, costs, and failure cases.
4. Check that the metric answers the operational question; separate measurements from modeled estimates.
5. Share a replication note, counterexample, or review through that project’s issue or pull-request workflow.

## Contribution standards

- Preserve each project’s problem statement and technical identity.
- Label integration paths as implemented, documented adapter, or candidate; diagrams alone do not prove a working connection.
- Do not infer production readiness, customer outcomes, certification, or performance from a portfolio listing.
- Include reproducible commands and environment details with benchmark claims.
- Report negative results and limitations with the same care as positive results.
- Keep credentials, private repository details, and confidential architecture out of public issues.

Use the [public project directory](PORTFOLIO.md) for the complete catalog and [benchmark protocols](BENCHMARKS.md) for measurement definitions. For scoped professional review, use the [A2Z SOC architecture-review contact](https://a2zsoc.com/contact?topic=architecture-review&utm_source=github&utm_medium=profile).

Project issues and pull requests are the place to ask technical questions and propose work. Maintainer response times and mentorship availability are not guaranteed unless separately agreed.
